# Eleven Overview (beta): design specification and implementation plan

## Authorization and scope
The user explicitly delegates the exploratory POC design, asks for a written internal plan first, Eleven Cards style, beta in the name and installation when verified. No additional design interview/approval is blocking: the POC is the instrument for deciding subsequent product direction. Do not publish, push, modify sibling card sources or change existing dashboard configuration. Install only the new standalone resource.

## Inspection and critical review
Existing collection has Energy, History and Timeline, scoped standalone builds, native ha-form editors, duplicate-registration guards, theme-derived surfaces, 16px content padding, 18px/650 headings, small secondary metadata and blue/orange/violet/teal series colors. Existing graphs are detail-oriented; an overview should lead with the current number, not reproduce axes, zoom, legend and hover controls at miniature scale. Avoid nested tile borders, decorative gauges, generic hero typography and implicit good/bad colors for arbitrary sensors. Workspace already contains unrelated History/Timeline edits: preserve them, and never install the rebuilt combined collection.

## Product and UI decisions
Name: Eleven Overview (beta); custom type: custom:eleven-overview-card. Intended for quick scanning on HA desktop/tablet/mobile, NL/EN and light/dark. One ha-card with a quiet heading and visible beta label, period metadata and aligned sensor cells. Each cell owns entity, optional label and color; global options own title, hours, automatic/1/2/3 columns, graph and delta visibility. Default 24h and automatic 2-column grid with narrow cards collapsing to one column. At most eight numeric sensor entities. Values use HA locale and units, tabular numerals. 16px outer padding, 18px heading, 28px values, 12px labels/meta, 4/8/16px spacing, 2px sparkline. Use existing palette, theme variables and native ha-card radius/border; no additional inner cards or gradients. All cells have equal independent settings.

## Data contract
Live value comes from hass.states, never from the history endpoint. Recorder provides a rolling selected-period sparkline and signed absolute difference from the held value at period start, in the sensor's own unit. Label explicitly says change since period start, not previous-day average. Require boundary coverage and compatible units for comparisons; missing/unavailable/bad numeric states create gaps, not zeros. No percentage when baseline is zero and no misleading green/red direction. Unknown/unavailable entity is shown explicitly. History failure retains live values and provides retry; no recorded history is distinct from loading/failure. Bounded refresh (60s), batch history request, no per-state-change API requests, invalidate stale in-flight responses, clean up timers on detach. Escape all configurable strings and validate color before CSS injection. Device control is out of scope; cell click/Enter opens native more-info only.

## Settings and states
Native ha-form global section followed by one expandable sensor entry each, entity selected once, label/color alongside it, add/remove/up/down buttons, immutably copied configs including frozen HA feedback. Native lazy form bootstrap reused from History. Stub chooses up to four available numeric sensors; editor can hold an empty draft but runtime requires at least one. Loading, error/retry, no-history, missing entity, unavailable current, constant/negative/zero data, long labels, malicious strings and history gaps must be tested. Keyboard focus visible, touch targets >=44px, no required hover or animation.

## Implementation order and files
1. Test-first pure config/numeric/history/sparkline helpers under cards/overview-card/tests and src. Vertical RED/GREEN slices for config, baseline/delta and gaps.
2. Test-first rendering/lifecycle/editor contracts, then src/overview-card.js and standalone build script. Preserve source-module testability and standalone scoping.
3. Update root build source list, four-card registration/picker and overlap assertions, documentation, per-card README and standalone QA fixture. Run full regression suite/checks; report unrelated baseline failures rather than hiding them.
4. Browser QA using synthetic fixture at 1280/390/320 light/dark, inspect screenshots, assert overflow, values, unavailable, error/retry, keyboard more-info and editor feedback. Then native HA preview/editor with real read-only Recorder history, including actual HA wrapper Save capture without dashboard persistence.
5. Discover fresh live resources/dashboard configs; backup and hash sibling modules. Atomic new-file install and new module resource, restore temporary SSH options/state/key. Read back exact resource, served bytes, sibling hashes and unchanged dashboards. Repeat browser QA against installed bytes.

## Acceptance and exclusions
Built, tested standalone artifact; picker name includes (beta); native editable options and independent sensors; meaningful current values and honest trends/delta; responsive and theme screenshots reviewed; live served bundle and editor exercised; only new resource installed; no automations/entities/dashboard configurations changed. No HACS release/publication or forced migration, no Compare/Heatmap features, no graph threshold editor, no invented history. Open decisions intentionally deferred to user feedback after POC: future layout density, extra contextual metrics and comparison semantics.
